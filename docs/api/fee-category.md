# 费用类别与医保分类口径

> 耗材计费单上的「费用类别」与「医保分类」不是随手填的 —— 它决定**住院收费票据的分区**、
> **医保结算清单的分区**，以及事后对账时 HIS 那边能不能勾上。填错时当场看不出毛病，
> 关台对账时才发现进了另一个分区，返工的是收费员与耗材管理岗。

这份文档说清四件事：院内 14 类费用口径是什么、耗材能落在哪一类、
医保分类怎么配、以及主数据填错了在**导入时**怎么被揪出来。

## 一、口径来源

口径出自院内「医疗收费信息」分区（domain 资产 `dictionaries/医保结算清单字段规范.md`）：

> 与医疗住院收费票据口径一致：结算期间、金额合计、甲乙类/自费/其他、
> **14 类费用**（床位 / 诊察 / 检查 / 化验 / 治疗 / 手术 / 护理 / 卫生材料 / 西药 /
> 中药饮片 / 中成药 / 一般诊疗 / 挂号 / 其他）、医保统筹基金支付等

本系统只做**口径一致性校验** —— 不做任何医学判断、不改主数据、不改业务状态。

口径的真源是 **`src/engine/fee-category.ts`**（判定引擎那一侧）。
数据合成层（`src/data/catalog.ts`）转出同一张表，
**不会出现「合成时按一套口径、判定时按另一套口径」的分裂**。

## 二、14 类费用口径与耗材适用范围

| # | 费用类别 | 耗材可落 | 允许的医保分类 | 一句话说明 |
|---|----------|---------|----------------|-----------|
| 1 | 床位 | 否 | 甲类 / 乙类 | 住院床位费：属基本诊疗项目，医保目录内 |
| 2 | 诊察 | 否 | 甲类 / 乙类 | 医生查房与诊断费：属基本诊疗项目 |
| 3 | 检查 | 否 | 甲类 / 乙类 | 影像与检验检查费：属基本诊疗项目 |
| 4 | 化验 | 否 | 甲类 / 乙类 | 实验室检验费：属基本诊疗项目 |
| 5 | 治疗 | 否 | 甲类 / 乙类 | 治疗操作费：属基本诊疗项目 |
| 6 | 手术 | 否 | 甲类 / 乙类 | 手术费：属基本诊疗项目 |
| 7 | 护理 | 否 | 甲类 / 乙类 | 护理费：属基本诊疗项目 |
| 8 | **卫生材料** | **是** | 甲类 / 乙类 / 丙类 | 医用耗材类：**耗材唯一允许落地的费用类别** |
| 9 | 西药 | 否 | 甲类 / 乙类 / 丙类 | 西药费：属药品类，耗材不得落在这里 |
| 10 | 中药饮片 | 否 | 甲类 / 乙类 / 丙类 | 中药饮片费：属药品类 |
| 11 | 中成药 | 否 | 甲类 / 乙类 / 丙类 | 中成药费：属药品类 |
| 12 | 一般诊疗 | 否 | 甲类 / 乙类 | 一般诊疗费：属基本诊疗项目 |
| 13 | 挂号 | 否 | 甲类 / 乙类 | 挂号费：属基本诊疗项目 |
| 14 | 其他 | 否 | 甲类 / 乙类 / 丙类 | 兜底类：未单列的费用落这里 |

**耗材只允许落在「卫生材料」类** —— 耗材落在药品类或诊疗床位类，
要么是主数据录错了类目，要么是这条根本不是耗材，都不该按耗材去计费。

## 三、医保分类（甲 / 乙 / 丙）

| 分类 | 含义 |
|------|------|
| **甲类** | 纳入医保支付范围，按规定比例支付（个人不掏） |
| **乙类** | 纳入医保支付范围，但按规定先行自付一部分 |
| **丙类** | **不纳入**医保支付范围，全部由个人支付（自费） |

取值**只能是这三个之一**：`甲类` / `乙类` / `丙类`。
写成「甲」「A类」「自费」「甲乙丙」都不合法 —— 那是写法问题，不是口径问题。

## 四、判定规则（四条，逐层短路）

判定顺序**先给最具体的原因码**：

| 顺序 | 条件 | 原因码 | 错误码 | 处置 |
|------|------|--------|--------|------|
| ① | 费用类别不在院内 14 类允许集内 | `FEE_CATEGORY_NOT_ALLOWED` | `ERR_FEE_CATEGORY_NOT_ALLOWED` | 按第二节的清单改费用类别名称 |
| ② | 医保分类取值非法（不是甲/乙/丙） | `INSURANCE_CLASS_INVALID` | `ERR_INSURANCE_CLASS_INVALID` | 改成「甲类」「乙类」「丙类」三选一 |
| ③ | 费用类别与医保分类的组合不在矩阵内 | `FEE_CATEGORY_INSURANCE_MISMATCH` | `ERR_FEE_CATEGORY_INSURANCE_MISMATCH` | 核对组合是否落在第二节的「允许的医保分类」列里 |
| ④ | 耗材落在了非材料类 | `FEE_CATEGORY_NOT_CONSUMABLE` | `ERR_FEE_CATEGORY_NOT_CONSUMABLE` | 耗材只允许落在「卫生材料」；若是药品请从耗材主数据里剔除 |

### 第 ③ 条的依据与口径说明

丙类 = 不纳入医保支付范围（全自费）。在医保结算清单口径下，
**不纳入支付范围的费用按「自费」列示、不带甲乙丙分类**；
而床位 / 诊察 / 检查 / 化验 / 治疗 / 手术 / 护理 / 一般诊疗 / 挂号
这些**基本诊疗与床位项目在医保目录内**，只能是甲类（全额）或乙类（部分自付）——
把它们写成丙类，在结算清单口径下不自洽，判错配。

耗材（卫生材料）与药品（西药 / 中药饮片 / 中成药）三类都允许：
高值耗材里甲类、乙类、丙类（全自费）三种都真实存在。

> **口径说明**：第 ③ 条的矩阵是**本项目采用的口径**（依据如上）。
> 若院内口径与此不同，改 `src/engine/fee-category.ts` 的 `FEE_CATEGORIES` 矩阵即可 ——
> **导入期差异清单与运行期绑定校验读的是同一张表，两处同步生效**。

## 五、两处生效点

| 生效点 | 位置 | 行为 |
|--------|------|------|
| **导入期** | `src/ledger/import-master-data.ts` | 不合规的行**照常导入**（主数据是院内权威，导入器不替耗材管理岗删行），同时登记到待补录清单 |
| **运行期** | `src/engine/validate-code.ts` 业务层 | 不合规的耗材在**绑定阶段**就被判异常，转人工核查条目，**不按错口径计费** |

业务层的判定顺序是：`active` → 费用类别缺项 → 医保分类缺项 → **费用口径自洽**
→ 单位口径自洽。前三项缺项各有独立原因码，费用口径与单位口径的问题也各走各的码。

## 六、主数据的问题在导入时就暴露

耗材管理岗维护的 `fee_category` 与 `medical_insurance_class` 两列，
把耗材录成「西药」、把医保分类写成「甲」、把床位费写成丙类，都很常见。
本系统的口径是：**问题在导入时暴露，不留到运行期才炸**。

- 导入器逐行做费用 / 医保口径检查；
- **问题行照常导入**，同时在**待补录清单**（`master_data_gap` 表）登记一条；
- 补录后重新导入且口径已合规 → 该耗材该类型的待补录条目**自动销项**。

待补录清单在 `doctor` 子命令里能直接看到：

```bash
node dist/cli.js doctor --db data/ledger.db
```

```
== 耗材主数据待补录（单位口径 / 费用口径） ==
  待补录 2 条，已销项 1 条
  MAT-FEE-DRUG           FEE_CATEGORY_NOT_CONSUMABLE  耗材不得落在费用类别「西药」：耗材只允许落在「卫生材料」类
  MAT-FEE-MISMATCH       FEE_CATEGORY_INSURANCE_MISMATCH  费用类别「床位」与医保分类「丙类」组合错配：该类别只允许 甲类 / 乙类
  补录主数据后重新导入即自动销项；口径见 docs/api/units.md 与 docs/api/fee-category.md
```

**单位口径与费用口径的缺口可以并存**：同一条耗材既缺换算系数、
费用类别又落错了类目，清单上**两条都在**，各修各的 —— 补好了单位口径
不会把还没修的费用口径那条一起销掉（唯一键是「耗材码 + 缺口类型」）。

## 七、升级前的老账怎么办

台账迁移的 **v15 版**（`fee_category_policy`）会把待补录清单的唯一键从
`material_code` 改成 **`(material_code, gap_type)`**：

- 只换索引，**老库的行一条都不丢**；
- 升级前同一条耗材只能留一条缺口（单位口径与费用口径互相顶掉），
  升级后两类缺口可以并存；
- 升级前已落库的耗材行**不追溯判定** —— 费用口径不合规的耗材，
  下一次导入时会被登记到待补录清单并开始被绑定引擎拒收。

## 八、验收

```bash
node --test dist/tests/fee-category.test.js
```

覆盖：14 类允许集与顺序、耗材只落材料类、合法组合放行、
费用类别不在允许集被拒、医保分类取值非法被拒、组合错配被拒、
耗材落在药品类被拒、导入期差异清单行数与不合规数据行数相等、
补录后自动销项、绑定阶段不合规耗材转人工且不落台账不计费、
老库 v14 → v15 升级不丢待补录行。
